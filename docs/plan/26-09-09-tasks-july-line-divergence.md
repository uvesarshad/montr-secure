- [x] **(A12, P1)** Fix real cross-platform path-handling bugs the Windows CI job surfaced. ROOT CAUSE CONFIRMED: ts-morph's `SourceFile.getFilePath()` always returns forward-slash paths, on every OS, while the `dir` these were compared against came from `node:path` (backslashes on Windows). Ten call sites across `packages/appmap/src/**` did raw `abs.startsWith(dir)` before normalizing separators, so on Windows the comparison always failed and every one silently fell through to returning the untouched absolute path instead of a repo-relative one — explaining routes/models/auth-boundaries/telemetry-surfaces all resolving to `undefined`/empty. This directly contradicts the source audit's untested conclusion that App Map path normalization was "fine" — that was never checked against a real Windows run until this task, and it did not hold. Fixed at all ten sites (`build.ts`, `diff.ts`, `routes.ts` ×2, `express.ts`, `callgraph.ts`, `fastify.ts`, `route-models.ts`, `surfaces.ts`, `taint.ts`) by normalizing `dir` to forward slashes before the comparison, not just the final output. Verified against a simulated Windows path pair (mixed separators) confirming the fix produces the correct relative path where the old code returned the full absolute path. Python/Java analyzers use fast-glob (always forward-slash) rather than ts-morph, so they were never affected — checked, not assumed. Two more bugs surfaced by the same investigation, both TEST-only (not product code): `tests/qa.corpus.test.ts` asserted `repo.path.startsWith("/")`, which is false for any Windows absolute path (`C:\...`) — fixed to use `node:path`'s `isAbsolute()`. `tests/stack-agnostic.invariant.test.ts` used `file.split("/").pop()` against a `node:path`-joined path, which no-ops on Windows (no `/` to split on) and silently defeats the file's own exception list — fixed to use `basename()`. All three fixes verified: full suite 168 files / 1918 passed / 2 skipped (stable across repeated runs, unchanged from baseline); typecheck clean; `eslint .` clean; turbo lint 37/37; prettier clean. CONFIRMED on an actual Windows runner (2026-09-11, run 34637132922, commit c1332b6): typecheck passed, and the unit-test step went from roughly two dozen real failures to **1 failed | 1917 passed | 2 skipped (1920)** — every App Map/route/model/auth-boundary/telemetry-surfaces/corpus-loader failure this task set out to fix is gone. The two `generate.agent-loop.test.ts` timeouts also did NOT recur this run (both passed) — encouraging, but one clean run isn't proof a timing-sensitive test can't flake again, so that item stays open below rather than being marked fixed. The single remaining failure was exactly the anticipated one: `fix.container-replay.test.ts`, failing on a Docker networking error (`could not find plugin bridge in v1 plugin registry`) — an environment limitation of the `windows-latest` runner, not a code defect.

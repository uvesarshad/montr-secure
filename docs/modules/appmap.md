# Module: Layer 0 Intake and App Map Generation

Scope: AST parsing across TypeScript, Python, and JVM stacks, route detection, ORM mapping, taint modeling, and cost estimation.
Rendering context: Server
Project tier: 4
Last updated: auto

Overview
The App Map module implements Layer 0 of the analysis pipeline within packages/appmap. It inspects repository source code to build a comprehensive structural map of the target application. Layer 0 discovers HTTP and API routes, database models, data store connections, external service calls, and potential taint sources and sinks. It simultaneously calculates token expenditure projections and dollar cost estimates before expensive analysis begins.

Entry Points and Core Runners
Layer 0 Runner: packages/appmap/src/runner.ts exports runLayer0AppMap, which orchestrates repository checkout, language detection, AST walking, and cost estimation.
Module Export: packages/appmap/src/index.ts exports public interfaces, AST builder functions, and schema definitions. AGENT SEE: also re-exports the Python/Java web-tree-sitter parser loaders + null-safe AST helpers (getPythonParser/parsePythonModule/pythonDescendants, getJavaParser/parseJava/javaDescendantsOfType), previously internal to languages/{python,java}/, purely additive — so packages/semantic-index's AST chunker (E5) can parse the same grammars through the same loaders instead of duplicating WASM-loading logic. No extraction behavior changed.

Key Components and Parsers
Language Extractors: Located in packages/appmap/src/languages, containing specialized AST parsers for TypeScript and JavaScript, Python (Django, FastAPI, Flask), and JVM languages (Spring, JAX-RS, JPA).
TypeScript Route Extractors: packages/appmap/src/languages/typescript/routes.ts covers Next.js (App Router and Pages Router). packages/appmap/src/languages/typescript/express.ts and packages/appmap/src/languages/typescript/fastify.ts cover Express and Fastify respectively, both ts-morph AST based and receiver-agnostic (match on the HTTP-verb call shape, not a fixed app/router identifier name). Express and Fastify extractors only run when languages/typescript/index.ts detects the matching framework dependency in package.json. Express resolves same-file app.use(mountPath, router) mount-prefix composition; cross-file router composition is not resolved. Fastify covers both the verb-call form and the app.route({ method, url, handler }) object form; app.register(plugin, opts) prefix composition is not resolved.
Auth-Boundary Detection (A20): routes.ts resolves each route's auth state through real AST control-flow analysis, not identifier-text regex, in order: an export wrapped in a verified HOC call (export const GET = withAuth(handler), or the factory form requireRole("admin")(handler) — the wrapping identifier is confirmed as an actual CALL, not a substring anywhere in the file); a root or src/ middleware.ts whose body references a known guard identifier, propagated to every route matched by its exported config.matcher (or every route when no matcher is declared, Next's own default) — the Next.js analog of Express/Fastify global middleware; only when neither resolves anything does the original whole-file guard-identifier-text scan run as the last-resort fallback (unknown otherwise). Python (python/routes.ts) additionally resolves Django 5.1+'s global django.contrib.auth.middleware.LoginRequiredMiddleware in a settings module's MIDDLEWARE list, propagating authenticated to every still-unknown URLConf route (the per-view @login_not_required opt-out is not resolved, since it typically lives in a different file). Java (java/extract.ts) additionally resolves Spring Security's declarative authorizeHttpRequests(auth -> auth.requestMatchers(...).hasRole(...)...) filter-chain lambda (also covers the legacy authorizeRequests/antMatchers/mvcMatchers spellings) into Ant-pattern-to-route-path matches, applied project-wide via the new applySpringSecurityAuth pass in java/index.ts; a route with its own per-method/per-class @PreAuthorize/@Secured/etc. annotation signal is never overridden by the filter-chain result.
Route-to-Model Linker: packages/appmap/src/languages/typescript/route-models.ts statically links each route's handler to the ORM model(s) it queries, populating Route.referencedModels (an array of { modelName, operations } where operations is a subset of read, write, delete). It resolves a direct prisma.<model>.<method>(...) call inside the handler, plus one hop through a locally declared helper function (same file or a relative import), mirroring callgraph.ts's own bounded-hop convention. It does not resolve through class-method/repository-pattern indirection (e.g. a route calling a repository object whose method internally calls Prisma) or through bare/workspace package imports — only relative imports are followed. Raw queries ($queryRaw/$executeRaw) are not attributed to a model since there is no static model name in the call.
Structural Builder: packages/appmap/src/build.ts aggregates discovered routes, ORM entities, and entry points into a normalized AppMap data structure. languages/typescript/index.ts merges the per-framework route scans (Next.js/Express/Fastify) before running the route-to-model linker.
Taint Surface Detector: packages/appmap/src/sources.ts identifies user-controlled inputs (query parameters, request bodies, route params, headers) as TaintSources and dangerous execution sinks (SQL queries, shell commands, file systems) as TaintSinks.
Diff Scoper: packages/appmap/src/diff.ts performs git diff analysis for diff-mode scans to limit the structural map to modified files and affected downstream dependencies.
Cost Estimator: packages/appmap/src/cost.ts measures repository size, route count, and AST complexity, querying packages/cost-meter to calculate estimated token and dollar costs.

Interprocedural Call Graphs (A21): each language now populates AppMap.taintFlows with a bounded, 1-2 hop interprocedural taint-flow resolver, all sharing the same TaintFlowEdge output shape. TypeScript's packages/appmap/src/languages/typescript/callgraph.ts (the reference implementation) resolves same-file and relative-import direct-call and return-propagated flows. Python's packages/appmap/src/languages/python/callgraph.ts mirrors it at full parity: module-level (not class-method) functions, same-file resolution, and one-hop from .module/from ..pkg.mod relative-import resolution — bare/absolute imports are out of scope. Java's packages/appmap/src/languages/java/callgraph.ts reaches same-class and same-file cross-class static-style method resolution; cross-file (same-package) resolution is explicitly NOT attempted, since Java requires no import statement for a same-package call and a directory-based approximation risks a false edge in a multi-module build — this is documented as a follow-up needing real package/import declaration parsing. Java's source detection additionally recognizes a bare identifier argument that is itself a Spring-annotated parameter (@RequestParam etc.) of the calling method, not only an inline source-shaped expression, since Java taint sources are established at annotated parameters rather than expressions like req.query. packages/confirm/src/static.ts's findSink/findSource now fall back to a matching taintFlows edge (resolving the real TaintSink/TaintSource record by exact location) whenever same-file lookup finds nothing — purely additive, and the same fallback that already made packages/correlation/src/grounding.ts's Layer 2 scoring cross-function-aware for TypeScript now also applies there for Python and Java.

Threat-Model Derivation (E6): packages/appmap/src/threat-model.ts runs as an additional step inside Layer 0's own execution, immediately after auth-boundary labeling and before persistence — not as a new pipeline layer. A closed six-member LayerId union threads through packages/contracts/src/queue.ts's QUEUE_NAMES and job-data union and every layer-keyed structure in packages/orchestrator, so inserting a real seventh layer id for this step was rejected as disproportionate for a step with no gate and no independent retry policy; packages/orchestrator/src/controller.ts and packages/contracts/src/queue.ts are unchanged by this feature. buildDeterministicThreatModel always runs, with no LLM required: it derives trust boundaries by grouping routes by authState, and an attack-surface plausibility rating per finding category grounded in the App Map's own taint-sink kinds, data-store kinds, and route-to-model fan-out (for example, no deserialize-kind taint sink anywhere marks insecure_deserialization and xxe as zero-surface; a raw SQL taint sink marks sql_injection as high-plausibility). When a gateway is wired, deriveThreatModel additionally lets the model append abuse-case scenarios and additional priority-category hints on top of that deterministic baseline; every model-proposed route path and category is validated against the real App Map and taxonomy before acceptance, and the model can never remove or downgrade a deterministic entry. The result is attached to AppMap.threatModel, including its scopeHints (priorityCategories, priorityRoutePaths, and the advisory-only zeroSurfaceCategories) that packages/discovery consumes to prioritize Layer 1 candidates — see docs/modules/discovery.md. This is a prioritization signal only; it never removes a category or a candidate that would otherwise run.

Database Models and Persistence
AppMap Model: Written to Postgres via packages/state-store. Stores languages, frameworks, entrypoints, data stores, ORM models, third-party calls, and taint flow graphs.
Route, TaintSource, TaintSink Models: Stored as relational entities linked to the parent AppMap, enabling fast indexed queries during Layer 2 correlation and Layer 3 confirmation.
Rebuild Policy: AppMap persistence honors rebuild policies (rebuild_on_stale_commit, always_rebuild, never_rebuild) to avoid re-parsing unchanged repository commits.

Constraints and Edge Cases
AGENT NOTE: Downstream pipeline layers (L1 through L5) must remain completely stack-agnostic. All language-specific AST nuances must be resolved within packages/appmap into standardized AppMap entities.
AGENT AVOID: Never attempt live network connections or clone remote repositories without validating workspace boundaries in packages/appmap/src/workspace.ts.
AGENT NOTE: Route.referencedModels is populated on the in-memory AppMap object returned by buildAppMap and is available to any consumer that reads that same object within the run. The Postgres Route model (packages/state-store/prisma/schema.prisma) does not yet have a column for it, so a Route reloaded from the database after a fresh appMaps.get() will not carry referencedModels — persisting it requires a Prisma migration on the Route table plus mapper changes in packages/state-store/src/mappers.ts (routeToCreate/routeFromRow), which is out of scope of the current change and tracked as a follow-up.
AGENT NOTE: AppMap.threatModel has the identical in-memory-only limitation as Route.referencedModels above — no Prisma column exists for it yet, so a reload from Postgres will not carry it. Within a single scan run, packages/orchestrator/src/persist.ts's persistLayerOutput caches the full validated Layer0Output (threatModel included) so Layer 1 and Layer 3 both see it via ctx.priorOutputs.layer0.appMap in that same process; only a resumed run in a fresh worker process falls back to the DB-reloaded map, which will be missing it. packages/confirm/src/types.ts's ConfirmInput already carries the full AppMap (used today for taintFlows lookups), so appMap.threatModel is already reachable there with zero interface change — Layer 3 consuming it for its own scope-hint prioritization is a documented, deliberately deferred follow-up (packages/confirm/src/** was intentionally not touched by this change).
